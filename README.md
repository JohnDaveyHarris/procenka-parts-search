# Подбор автозапчастей и аналогов — тестовое задание

Клиентское React-приложение для интеграции с внешним API-сервисом поиска
автозапчастей и аналогов «Проценка» (Favorit Parts, `wsprice`).

Интерфейс реализует **двухэтапный процесс подбора номенклатуры**:

1. **Этап 1 — Производители.** Пользователь вводит артикул; запрос выполняется
   по факту ввода (debounce 450 мс, минимум 3 символа). Отображается список
   производителей с наличием и минимальной ценой.
2. **Этап 2 — Аналоги и предложения.** При выборе производителя выполняется
   повторный запрос с `brand` + `analogues=on` (+ `info=on`). Отображается
   итоговая таблица: название / производитель, цена, остаток на складах,
   детализация по складам.

## Стек

- **React 19** (компоненты, хуки) — без TypeScript, чистый JavaScript (JSX)
- **Redux Toolkit** (`createSlice`, `createAsyncThunk`) + `react-redux` — управление состоянием
- **Bootstrap 5** — сетка, утилиты, базовые компоненты + авторский CSS-слой (минимализм)
- **Next.js 16 (App Router)** — окружение запуска; вся логика приложения клиентская
- Шрифт Inter (next/font, кириллица), без UI-библиотек «тяжелее» Bootstrap

## Запуск

Требуется **Node.js 20.9+** (Windows, macOS, Linux).

```bash
npm install
npm run dev       # http://localhost:3000
```

Продакшен-сборка: `npm run build`, затем `npm run start`.
Все npm-скрипты кроссплатформенные — работают в cmd, PowerShell и bash.

Переменные окружения (опционально, см. `.env.example`):

```
HSPRICE_BASE=http://api.favorit-parts.ru/hs/hsprice/
HSPRICE_KEY=00000000-0000-0000-0000-000000000001
```

Ключ покупателя хранится на сервере и клиенту не передаётся.

## Ключевые решения

### Почему есть серверный прокси `/api/hsprice`

Внешний сервис отвечает только по **http** и не отдаёт CORS-заголовки, поэтому
браузер блокирует прямые запросы со страницы (mixed content + CORS). Прокси —
тонкий pass-through: пробрасывает только разрешённые параметры (`number`,
`brand`, `analogues`, `info`), кодирует спецсимволы через `URLSearchParams`
(требование документации) и возвращает JSON «как есть». Вся бизнес-логика —
на клиенте. При деплое чистого SPA достаточно заменить `PROXY_URL` в
`src/services/hspriceApi.js` на адрес своего прокси/бэкенда.

### Цены — только из складов

Поле `price` у позиции устарело («НЕ ИСПОЛЬЗОВАТЬ» по документации), поэтому
цена считается из массива `warehouses` (минимальная цена среди складов
с остатком; при отсутствии остатков — минимальная доступная). Склады
сортируются: сначала с остатком, по возрастанию цены — чипы показывают лучшие
предложения. Дата отгрузки и признак «собственный склад» — в подсказке чипа.

### Обработка состояний и ошибок

- **Загрузка** — скелетоны, повторяющие итоговую раскладку каждого шага.
- **Ошибки API** (`Empty key!`, `Request quota exceeded!`, …) — единый блок
  с текстом ошибки и кнопкой «Повторить запрос»; `error` обрабатывается и как
  строка, и как массив строк.
- **Сетевые сбои / таймауты** (18 c на прокси) — понятное сообщение + retry.
- **Пустой ответ** — документированная «заглушка»
  (`goodsID = 00000000-…-0000`, пустые поля) отфильтровывается, показывается
  empty-state с подсказкой.
- **Нулевые остатки** — позиция отображается приглушённо с бейджем «нет».
- **Невозвратные позиции** (`info=on`) — бейдж «невозвратная» у позиции и склада.
- **Гонки запросов** — `createAsyncThunk` фиксирует `requestId`; ответы
  устаревших запросов игнорируются в reducer'ах.

### Прочее

- Кнопка «Подобрать» не нужна: запрос уходит автоматически через 450 мс после
  остановки ввода (минимум 3 символа); Enter выполняет запрос мгновенно,
  без ожидания debounce.
- Тёмная тема: переключатель в шапке. Выбор сохраняется в localStorage,
  по умолчанию берётся системная схема (`prefers-color-scheme`). Тема — это
  атрибут `[data-theme="dark"]` на `<html>` и набор CSS-переменных; инлайн-скрипт
  в `layout.jsx` применяет её до первой отрисовки — без «вспышки» светлого фона.
- Сортировка предложений: искомая деталь → в наличии → по возрастанию цены.
- 740+ предложений разбиты порциями по 25 («Показать ещё») — состояние
  в redux, переживает смену производителя.
- Смена артикула после выбора производителя автоматически возвращает процесс
  к шагу 1 (новый запрос), снятие выбора по чипу — мгновенный возврат к шагу 2
  без повторного запроса.
- Доступность: семантические теги, `aria-live` для результатов, `visually-hidden`
  label, клавиатурная навигация, `prefers-reduced-motion`.
- Адаптивность: сетка брендов 2/3/4 колонки, склады переносятся в ячейку
  названия на узких экранах, таблица прокручивается горизонтально.
